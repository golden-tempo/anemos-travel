# Flight search providers (Duffel / SerpApi swap)

- The `optimize_for` field on flight search accepts only `"cost"`, `"time"`, or `"balanced"` (empty defaults to balanced).

- **Baggage-aware flight search** (specs/traveler-baggage): flight search (and the agent's `search_flights`) accepts `baggage` ∈ `personal_item` | `carry_on` | `checked`, and **the tier is never implicit** — `resolveBaggageTier` (`duffel_service.go`) is the one fallback chain (stated → the traveler's `traveler_preferences.baggage` → `defaultBaggageTier`, which is **carry_on**, because quoting a bare fare as "cheapest" is how a traveler pays a cabin-bag fee the ranking never saw). `/flights/search` is unauthenticated so it can't read the profile: the two callers with identity resolve it and send it explicitly — `runSearchFlightsTool` from `planSession.bagPref` (also its validation boundary; an unrecognized tier used to behave silently as carry_on) and the Flutter screen from the saved profile. The response echoes the RESOLVED tier plus `baggage_note`, a stable code (never prose) for a bag the provider could not price, localized client-side. Included allowances are parsed from every Duffel offer (`included_carry_on`/`included_checked`, worst case across segments/passengers); on carry_on/checked searches, `searchFlightsWithBaggage` (`flight_baggage.go`) fetches Duffel bag prices for the top `bagFeeTopK`=10 offers lacking the bag (one extra `GET /air/offers/{id}?return_available_services=true` each) and everything re-ranks on `effective_price` (fare + `bag_fee`); offers with `baggage_status:"unknown"` always sort last, and a status the PROVIDER already set is left alone (it priced the bag itself). `personal_item` short-circuits — zero extra calls, no baggage fields emitted. Dedup keys on schedule **+ bag-included bit** so bag-inclusive fare brands survive keep-cheapest collapse. `summarizeOffers` states the bag basis ONCE in its header (`baggageBasisClause`) — identical for every offer, and derived from what came BACK, never from what was asked for.

- Flight search inputs are **IATA codes** (e.g. `JFK`, `CDG`), not city names — resolve names via `/flights/airports?q=` first. Flight data comes from **Duffel** (`duffel_service.go`, process-wide `duffelService` singleton, static `DUFFEL_ACCESS_TOKEN`); the provider is isolated to that one file behind the `FlightOffer`/`Airport` types so it can be swapped without touching the handler, optimizer, or Flutter app.

- **Temporary flight-offers swap** (`serpapi_flights_service.go`): `FLIGHT_OFFERS_PROVIDER=serpapi` + `SERPAPI_API_KEY` routes the OFFERS search (only) to SerpApi Google Flights via the `flightOffersSearch` seam in `flight_baggage.go` — real data while the prod Duffel token is test-mode. Airports/IATA resolution stay on Duffel. While active: bookable offer searches send `deep_search` for Google-Flights-page price parity (15-45s slower; connectivity probes stay shallow via `FlightSearchRequest.Indicative`, with a `deep`/`shallow` cache-key split), Duffel's per-offer `fetchBagFees` is skipped (synthetic ids would 404) and bags are priced by Google instead — a carry_on/checked search sends `bags` = one per traveler entitled to one, so quotes come back bag-inclusive with `baggage_status:"in_price"` (fee not itemized) and **the bags count is part of the offers cache key**, since prices now vary by it. SerpApi exposes no checked-bag parameter and Google folds checked fees in on US domestic routes only, so a checked search is cabin-priced and says so via `baggage_note: checked_not_priced` — never an invented estimate. `check_flight_connectivity` rides the swap with a 3-candidate clamp + daily-quota headroom guard (reports unavailable rather than starving `search_flights`; `plan_connectivity.go`), and a failed search degrades to a Google Flights deep link inside `search_flights` (success, not error). Quota guards: 15-min offers cache + `SERPAPI_SEARCHES_PER_DAY` (default 50) + `serpapi_flights_*` counters in `/admin/ops/metrics`. Unset env = Duffel, byte-identical. Remove the whole seam when the Duffel live token lands.
