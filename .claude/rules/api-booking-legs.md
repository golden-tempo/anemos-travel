# Derived legs, booking todos & transport mode

- **Derived-leg identity & per-trip endpoints** (`booking_todo_identity.go`, `plan_trip_origin.go`, migration 00064; specs/trip-endpoint-airports): a derived transport row's identity is NOT its endpoint labels. The two home legs key on a reserved `@home` token whose POSITION carries the direction (`transport:@home>>amsterdam` / `transport:rome>>@home`), with `role`/`origin_label`/`destination_label` as columns — so changing an airport is an in-place title/label update the batch upsert already performs, and the two directions never collide (a trip can leave from ALB and come home into EWR). Before this, the label WAS the key, so any change deleted the row and took the booked flag, the per-leg mode (00055) and the linked expense's source (00061, no FK) with it — which fired on an ordinary Settings home-airport edit, on every trip the traveler owned. **Canonicalization is server-side in `syncBookingTodosHandler`, never posted by the client**: that is what makes a stale tab, an old cached bundle, or a collaborator's device land on the SAME row instead of pruning it, and the home legs' labels are then taken from the TRIP (`origin_airport ?? origin ?? the OWNER's home_airport`), which is what stops a collaborator retitling the owner's flights. `@` rather than a bare `home` because `namesAPlace` accepts "home" as a city. The wire still carries the endpoint-labelled key (`displayBookingTodoKey`) so every client matcher and the analytics history keep working; it dies at the specs/server-booking-todos flip. The prune **demotes** rather than deletes: a stale auto row carrying a booked flag, a mode, or an expense link becomes `auto = false` (an ordinary row in "Other bookings" that can actually be removed — `DeleteBookingTodoNonAuto` refuses auto rows, so skipping would leave a zombie). `trips.origin_airport`/`return_airport` are written TOGETHER or not at all (paired CHECK): null never means "same as the other direction". `set_trip_origin` refuses an airport on a stated ground trip (the "EWR → Montreal" incident 00062 was written for) and confirms any code against the airport lookup, because `resolveIATA` waves any three letters through. **The write has exactly one implementation, `applyTripEndpoints` (`plan_trip_origin.go`)**, called by that tool and by the trip page's `PUT /trips/{id}/endpoints` (`trip_endpoints_handler.go`, wave 2) — pinned by `TestPageAndChatWriteTheSameEndpoints`; the handler **400s a one-sided body** because `columns()` otherwise copies one airport onto the other, which would turn "change the outbound" into a silent rewrite of the leg home. `BookingTodoResponse.role` rides the wire so the client can offer "Change departure/return airport…" on exactly the two home legs instead of re-inferring which they are. On the page, a confirmed segment fills a derived leg's slot only when it connects **BOTH** endpoints — `segmentConnectsLeg`/`fuzzyMatch` in `trip_detail_derivation.dart` are the Dart twin of `segmentConnects`/`fuzzyMatch` (`trip_review.go`), with the same fixture table on both sides; matching on the destination alone is what let an `ALB → Amsterdam` segment nest under the `EWR → Amsterdam` leg and read as covered while Trip Health still counted the flight as a gap.

- **Booking shortlist** (`booking_option_handler.go`, `booking_option_choose.go`, migration 00065; specs/booking-shortlist): saved candidates hang off a **`booking_todos.id` FK** (NOT NULL, CASCADE) — the row that IS a leg's identity since 00064 — never off a `todo_key` string, because keying on the key would re-introduce a client-derived identity the server has to canonicalize and would bake in the doomed `displayBookingTodoKey` spelling. There is deliberately **no `kind` column** (it is the leg's kind; stored twice it can drift, since `UpdateBookingTodo` permits kind edits on the `auto=false` rows that demoted legs become). `price`/`currency` are a **both-or-neither pair** (CHECK + handler) because there is no FX anywhere in this app — a price in another currency is reported `expense_skipped: "currency_mismatch"`, never converted. **Promotion MUST stamp `auto_key` with the leg's storage key**: `_computeGroupedBookings` matches a stay by `autoKey == 'stay:<label>'` FIRST and only then by a name/address `contains` against the city label, which "Loft near Old Town" fails — an unstamped record renders in "Other bookings" instead of under its leg. Promotion is an upsert on `(trip_id, auto_key)`, so switching winners rewrites one row rather than growing a second stay per city. The winner link is **two typed FKs** (`ON DELETE SET NULL`), diverging from 00061's untyped pair for a stated reason: a promoted record is `auto=false`, outside sync ownership, so the FK is safe and gives un-choose for free — but the cascade deliberately does NOT clear `booked`, which is traveler state. `DemoteStaleAutoBookingTodos` gained a fourth predicate so a removed city demotes its leg instead of CASCADEing the traveler's research away. `upsertLinkedExpense` (extracted from `addExpenseHandler`) is the one implementation both the budget POST and `choose` use.

- **How a leg travels** (`leg_transport_mode.go`, migration 00068; specs/leg-transport-mode): `resolveLegMode` is the ONE answer to "how does this trip get from A to B", and every consumer calls it — the booking-todo sync, `checkTransit`, the model-facing `legTransportSummary`, `set_leg_transport_mode`. Ladder, highest first: **`booking_todos.mode`** (a choice somebody made — the row menu or the planner) → **a bookable ferry pair** (BOTH endpoints resolve via `ferryPortCode`; above the trip's mode because you can't drive between islands) → **`trips.travel_mode`** when it names a mode (`'mixed'` is not a mode, it's the statement that legs differ, so it falls through) → **geography** → **`flight`**. `geoLegMode` answers only when sure: both endpoints need `computeTripLegs` coordinates (which is what keeps the two HOME legs flights — an IATA code has none), `islandGroup` ends the analysis on a sea crossing (same island is still fine: `Palermo → Catania` is a train; **Great Britain is deliberately not a group** — the Chunnel makes `London → Paris` one), and `railRegions` is a `{bbox, maxKm}` table (Europe+GB and Japan at 550 km) so a new network is a row, not a branch. Every "no opinion" lands on the pre-00068 behaviour, so the rule can only move legs from wrong to right. A sea crossing is **never** answered `ferry` outside the Greek ports: `ferryhopperURL` degrades to a landing page for unknown ports, and a mode we can't route is worse than the flight search. **Two mode columns, two meanings**: `mode` (00055) is a choice and is preserved across syncs; `derived_mode` (00068) is what the server worked out and is REFRESHED with the `provider`/`search_url` the same derivation decides — readers resolve `mode ?? derived_mode` and never invert it, and `derived_mode` stays out of `DemoteStaleAutoBookingTodos`' predicate (that predicate lists what a traveler would lose). The sync resolves the mode **server-side instead of trusting the posted `provider`**, for the 00064 reason (a stale tab, an old bundle and a collaborator must land on the same answer) — which also closed 00055's logged trade-off about a stale client rewriting an overridden leg's link. Client-side, `BookingTodo.effectiveMode` feeds `_deriveTodos`' `modeByKey`, the row icon and the menu checkmark; the local `greek ? ferry : (ground ?? flight)` default is now only the **pre-sync bootstrap**. `_syncBookingTodos` re-derives inside the same `setState` because a row's TAP TARGET comes from the `_flightLegs`/`_ferryLegs` registries, not from the row — without it a leg reads "train" and still opens the in-app flight search. Agent side: `legTransportSummary` rides `create_itinerary`, `update_itinerary_section` and `get_trip` (a planner that can't see the app's answer can't correct it — that is why the Italy chat narrated flights), and `set_leg_transport_mode` (registry TAIL, `authedOnly` to keep the anonymous tools array byte-identical) writes `booking_todos.mode` through the same `SetBookingTodoMode` the row menu uses, **refusing with the trip's real leg list** rather than writing an orphan.
