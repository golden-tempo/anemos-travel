# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A travel route planning platform with two packages:
- **Go API** (`src/packages/api/`) — REST + SSE backend for route optimization, Google Places, and AI planning
- **Flutter app** (`src/packages/flutter-app/`) — Material 3 web/mobile frontend using Riverpod

A single **nginx gateway** on port **3000** serves the Flutter UI and proxies `/api/v1/` to the Go API, keeping everything same-origin.

## Parallel Development

Feature waves run as parallel **lanes**: one lane = one branch = one git
worktree (`make wt-new NAME=…`, own dev stack on its own ports) = one PR. Lane
agents STOP at PR-open (`ship pr` — never merge); one integrator session
(`/integrate`) merges them serially **in the order the PRs were opened** —
checking each for conflicts with `main` first and merging straight away when
there are none, otherwise merging `main` in, resolving hub files and
regenerating generated code (`store/`, `lib/l10n/app_localizations*.dart`,
`*.g.dart` are NEVER hand-merged — regen LAST) before it merges. Nothing is
rebased or force-pushed. Deploys run in the background and never block the next
merge; a red one stops the queue. Wave planning reserves goose migration
numbers; at most one in-flight lane may touch
`trip_detail_screen.dart` or append to `plan_tool_registry.go`. Full rules and
runbooks: [`docs/parallel-dev.md`](docs/parallel-dev.md). Triggers: `/wave`
(orchestrate a wave; also `status`/`abort`) and `/lane` (bootstrap one lane).

**Auto-lane on execute**: when executing an approved plan (or starting any
multi-file feature work) from the **main checkout**, first create a lane —
`make wt-new NAME=<feature-slug>` — and do all the work inside that worktree;
`ship` then stops at PR-open automatically and the integrator merges.
Single-file fixes and doc touch-ups may stay on a main-checkout branch.

## Architecture

### Go API (`src/packages/api/`)

All files in `package main`. Key files:
- `main.go` — HTTP server (gorilla/mux), middleware, and all route handlers
- `route_optimizer.go` — Nearest Neighbor + 2-Opt algorithm for location-level routes; defines `RouteRequest`, `RouteResponse`, `Location`, `OperatingHours`
- `places_service.go` — Google Places API integration (Text Search, Autocomplete, Details); reads `GOOGLE_PLACES_API_KEY` env var
- `plan_handler.go` — Streaming SSE endpoint (`POST /api/v1/plan`) backed by `anthropic-sdk-go`; agent loop (`aiModel()`, default claude-sonnet-4-6) dispatches through the ordered tool registry in `plan_tool_registry.go`; `plan_compactor.go` summarizes long histories with `aiModelLight()` (default Haiku 4.5); reads `ANTHROPIC_API_KEY` env var. Models and base URL are env-swappable to any Anthropic-compatible provider (see `anthropic_client.go` + `.env.sample`; e.g. Moonshot/Kimi)
- `db.go` — pgx connection pool (`dbPool`) + embedded goose migrations (`migrations/*.sql`); reads `DATABASE_URL`
- `store/` — **sqlc-generated** type-safe DB code; the only non-`package main` code in the API. Generated by `make api-sqlc` from `query/*.sql` + the migration schema; never hand-edit. (Created with the first queries; not present until then.)

The API runs on port **8080**. `WriteTimeout` is set to `0` (unlimited) to support the streaming `/plan` endpoint. Migrations apply automatically on boot; a missing/unreachable `DATABASE_URL` starts the API in **degraded mode** (stateless endpoints still work; `/health` returns 503 with the DB status).

### Flutter App (`src/packages/flutter-app/`)

State management: **Riverpod** (`ProviderScope` wraps the whole app).

- `lib/services/api_client.dart` — HTTP client; base URL configured via `--dart-define=API_BASE_URL` (defaults to `http://localhost:8080/api/v1`)
- `lib/services/places_api_service.dart` — Wraps places endpoints
- `lib/services/plan_service.dart` — SSE streaming client for `/plan`
- `lib/providers/` — Riverpod providers (one per feature: route, country, places, plan, api_client)
- `lib/screens/` — `HomeScreen`, `AgentScreen` (plan chat), `TripsListScreen`, `TripDetailScreen`
- `lib/models/` — Dart models matching Go API JSON; `.dart` files are hand-written, `.g.dart` files are generated by `json_serializable`

**Model code generation**: Any change to a model annotated with `@JsonSerializable` requires running `make flutter-build-models` to regenerate the `.g.dart` file.

### Docker / Gateway

- `dockerize/development/` — Flutter dev server + API + nginx (hot reload)
- `dockerize/deployment/` — Multi-stage: builds Flutter web, serves static, proxies API

Flutter is built with `--dart-define=API_BASE_URL=/api/v1` in Docker, so API calls are same-origin relative paths through the nginx proxy.

## Environment Variables

Create `src/packages/api/.env` (see `.env.sample`):
```
GOOGLE_PLACES_API_KEY=...       # Required for /places/* endpoints
ANTHROPIC_API_KEY=...           # Required for /api/v1/plan SSE endpoint
DUFFEL_ACCESS_TOKEN=...         # Required for /flights/* endpoints (Duffel; test or live token)
FLIGHT_OFFERS_PROVIDER=...      # TEMPORARY: "serpapi" routes flight OFFER searches to SerpApi Google Flights (real data while the Duffel token is test-mode); unset = Duffel
SERPAPI_API_KEY=...             # SerpApi key for the temporary swap (free tier 250 searches/mo)
TICKETMASTER_API_KEY=...        # Required for /events/* endpoint (Ticketmaster Discovery; free key)
TRANSCRIPTION_API_KEY=...       # Voice-dictation fallback (/transcribe); any OpenAI-compatible /audio/transcriptions provider — defaults target Groq
TRANSCRIPTION_BASE_URL=...      # Default https://api.groq.com/openai/v1
TRANSCRIPTION_MODEL=...         # Default whisper-large-v3-turbo
GOOGLE_OAUTH_CLIENT_ID=...      # Sign in with Google (server-side OAuth), with...
GOOGLE_OAUTH_CLIENT_SECRET=...  # ...this; register <PUBLIC_BASE_URL>/api/v1/auth/google/callback as redirect URI
APPLE_TEAM_ID=...               # Sign in with Apple (specs/apple-sso): Team ID, plus...
APPLE_CLIENT_ID=...             # ...the Services ID, ...
APPLE_KEY_ID=...                # ...the .p8 key id, and...
APPLE_PRIVATE_KEY=...           # ...the .p8 PEM base64-encoded onto one line
SENTRY_DSN=...                  # Optional error alerting; empty => Sentry fully inert
DATABASE_URL=...                # Postgres connection; absent/unreachable => degraded mode (no persistence)
```

Without `GOOGLE_PLACES_API_KEY`, place search endpoints return errors. The `/plan` handler also calls `search_places` internally, which will fail without the key. Without `DUFFEL_ACCESS_TOKEN`, the `/flights/*` endpoints return a configured-error; the rest of the API is unaffected. Without `TICKETMASTER_API_KEY`, the `/events/search` endpoint (and the `/plan` agent's `search_events` tool) returns a configured-error; the rest of the API is unaffected. Without `TRANSCRIPTION_API_KEY`, the dictation fallback is disabled (`/transcribe/availability` reports it) and the mic only appears in browsers with built-in speech recognition. Without the `GOOGLE_OAUTH_*` pair, the Google button is hidden and `/auth/google` answers 503; likewise the four `APPLE_*` vars gate the Apple button and `/auth/apple`; email+password auth is unaffected either way. `FERRYHOPPER_AFFILIATE_ID` is optional — ferry links work without it (just unattributed). `.env.sample` documents further optional vars: `SMTP_*` (verification/reset email; empty => tokens are logged instead), `PUBLIC_BASE_URL`/`PUBLIC_APP_PATH`, `ALLOWED_ORIGINS` (CORS, dev-only), `BOOKING_AFFILIATE_ID`, `PORT`, free-cap tuning (`FREE_*`), `ANTHROPIC_BASE_URL` + `ANTHROPIC_MODEL` + `ANTHROPIC_MODEL_LIGHT` (Anthropic-compatible provider swap, e.g. Moonshot/Kimi — also the fake-Anthropic test seam; unset = real Anthropic with the default Claude models), and `SENTRY_RELEASE`. `SERPAPI_HOTEL_SEARCHES_PER_DAY` (default 8; an explicit `0` means zero, not "default") and `HOTEL_RATES_CURRENCY` (default USD) tune `search_hotels`, which shares `SERPAPI_API_KEY` but is independent of the flights swap. With `FLIGHT_OFFERS_PROVIDER=serpapi`, `SERPAPI_BASE_URL` (test seam) and `SERPAPI_SEARCHES_PER_DAY` (quota guard, default 50) also apply — see the temporary-swap bullet under Key Constraints.

## Key Constraints

- `Location.Latitude` and `Location.Longitude` in the Go API are `*float64` (pointers) to distinguish "not provided" from zero — coordinate validation is skipped when nil to support name-only location resolution.
- The `/plan` endpoint uses `text/event-stream` with `http.Flusher`; the server `WriteTimeout` must stay at `0`.
- **The `/plan` tool registry order is part of the prompt-cache prefix** (`plan_tool_registry.go` header comment): the registry is an ordered slice serialized as the tools array, covered by the system-prompt cache breakpoint — keep existing entries byte-stable and **append new tools at the tail**. One registry entry per tool (definition + optional availability gate + dispatcher); the handler generates the tools slice and dispatches `tool_use` blocks from it.
- **Conversation compaction** (`plan_compactor.go`, specs/conversation-compaction) replaced the old hard "conversation too long" failure: when a `/plan` request's history reaches 24 messages, all but the newest 10 are folded into a state summary via one forced-tool `aiModelLight()` call (default Haiku 4.5); the summary streams back as an SSE `compacted` event and **the client owns it** — later turns resend it as `PlanRequest.Summary` in place of the folded messages. `planMaxMessages = 60` remains only as a runaway/abusive-client backstop (friendly SSE `error` event, not a 500).
- **Plan chats persist from the very first turn** for authenticated, non-trip-bound sessions with a `chat_id` (`plan_chat_sessions` table, migration 00031; specs/continue-where-you-left-off): two best-effort whole-transcript upserts per turn (synchronous at start, deferred at end with the streamed assistant text). "Graduation" is read-time, not a write: `GET /api/v1/chats` excludes chats whose `chat_id` already belongs to a trip (`NOT EXISTS` against `trips.chat_id` in `query/chat_sessions.sql`). Anonymous, degraded-mode, and trip-bound sessions stay ephemeral; sessions idle for two months are pruned opportunistically by the list handler.
- **Chat photo cards**: `search_places` emits a `places` SSE side event (≤8 cards; photo refs are `json:"-"` on `PlaceSearchResult` so the model-facing tool_result and public `/places/search` JSON stay byte-identical), and `search_local_recommendations` enriches its SSE payload with venue `photo_ref`s via `fields=photo` details lookups (`enrichLocalRecPhotos`, bounded + time-boxed; agent path only — public `/local/*` browse responses never carry photo fields). Images load through `GET /api/v1/places/photo` (`places_photo_handler.go`), a 302-redirect proxy gated by `knownPhotoRefs` (only refs the process handed to a client are servable — every Place Photo call is billed) with its own rate bucket. Flutter renders the strips in `_ResultStrips` (`chat_panel.dart` → `place_photo_card.dart`, fixed 200×160 cards so images can never reflow the chat tail); the places strip is suppressed on itinerary turns (`search_places` doubles as geocoding there). Strips replaced the local-picks/events summary chips; flights/ferries/event-links keep chips.
- **Uptime history** (`health_samples`, migration 00059; specs/uptime-history): every health-monitor tick persists an **interval with a state** (`covers_from`→`observed_at`; `tick` rows carry the three signal booleans SEPARATELY — never a joined reasons string, so a stale backup structurally cannot tint the availability bar). The sampler can't observe its own downtime, so absence is written down, not inferred: at boot `bootstrapSamples` writes an explicit `gap` row whose cause comes from the release comparison (changed `SENTRY_RELEASE` = `deploy` → unobserved/unknown seconds; unchanged = `unknown` → downtime — deploys never dent the number, unexplained restarts do). A tick observing `db_ok=false` can't write (the DB is what's down); `writeSample`'s bounded in-memory buffer holds it and flushes with the ORIGINAL timestamp on recovery. `rollupUptime` (`ops_uptime.go`) is the ONE place any of this becomes per-day state; the wire carries dense 90-day arrays, `uptime_pct: null` (not 0) for `no_data` days, and stable reason codes localized client-side. Pruned at 100 days by the janitor.
- **AI-provider health** (`ai_health.go`): every Anthropic SDK call site (`Messages.New` / `NewStreaming`) must call `recordAIResult(err)` exactly once per call — nil records a success. The process-lifetime tracker feeds `computeHealthState`'s third signal, so fatal failures (billing/auth; the credit-balance outage class) flip the shared ops degraded verdict and the `ops_monitor.go` self-check alerts admins on any reason-set change (passive — the monitor never pings paid providers; recovery requires a successful AI call; transient/unknown errors count in `/admin/ops/metrics` `ai_*` but never alert; unrecognized provider envelopes — Kimi/Moonshot — never classify fatal). Cadence: `HEALTH_TICK_MINUTES` (default 5).
- `/transcribe` has its own request lanes: a 10 MiB body-limit branch in `bodyLimitMiddleware` (`middleware.go`; default is 256 KiB, `/plan` gets 20 MiB for chat history incl. images) and its own IP rate-limiter bucket in `main.go`, separate from the `strict` (5/min) bucket so dictation traffic doesn't starve `/plan`.
- **MCP connector** (`mcp_server.go`, `mcp_tools.go`, `oauth_provider_handler.go`, specs/mcp-connector): we act as an OAuth 2.1 **provider** (public clients + PKCE S256 only, no secrets; tokens hashed at rest with `gt_*` prefixes; code reuse revokes the tokens that code minted; refresh rotates). The MCP server runs **stateless** — the SDK's per-request `getServer` hook builds a server whose tool handlers close over that request's authenticated caller, so no tool can reach another user's data (asserted by a two-connector test). `mcpAuthMiddleware` mirrors `authMiddleware` incl. the 503-vs-401 distinction, and 401s carry the `WWW-Authenticate: Bearer resource_metadata=…` challenge clients need to rediscover/refresh. Rate limiting is **per grant** on `/mcp` (IP tiers can't bound a connector — vendors egress shared IPs) and on its **own IP bucket** for `/oauth/*` (linking is 5 rapid calls; the strict tier would let one user's link throttle another's). Everything 404s unless `MCP_ENABLED=true`; `/api/v1/oauth/connections` stays reachable regardless so a grant can always be revoked. **Consent assumes a signed-out arrival**: `authorize/context` is deliberately public (the request token IS the credential, so the screen can render pre-session), which means the *client* owns the sign-in gate — `connect_app_screen.dart` waits for `AuthState.initialized` (never trusts the optimistic warm-boot `isSignedIn`), hands off to sign-in itself rather than showing an approve button that would 401, and persists the request token via `PendingConnectStore` first because SSO is a full-page navigation that returns at `/sso/<code>` with no memory of the route — `sso_callback_screen.dart` resumes `/connect/<token>` from it. A 401 from `authorize/decision` is typed (`ConnectAppUnauthorized`) and routes to sign-in; never fold it into a generic error. **`create_trip` accepts an optional free-text `origin`** (`trips.origin`, migration 00062) — where the traveler said they set out from, in their own words. It beats the saved home airport when titling the derived transport legs, and having no coordinates it draws no map pin (the trip's own `origin_airport` does — see the endpoints bullet below). It is **no longer write-once** (00064 removed the reason), but it still has exactly one writer, the agent's `set_trip_origin`; PATCH ignores it, pinned by `TestPatchTripCannotSetOrigin`. **Every tool carries directory-grade annotations** (`Title` + `readOnlyHint`/`destructiveHint`/`openWorldHint`) because missing or wrong ones are a named rejection cause in both the OpenAI plugin directory and the Anthropic connectors directory (specs/openai-plugin-listing) — and `DestructiveHint`/`OpenWorldHint` are `*bool` whose **nil means TRUE**, so a hint left unset ships absent and reads as the dangerous meaning; state every hint outright and let `TestMCPToolsCarryDirectoryAnnotations` (which asserts against what the *client* received) keep it that way. `ServerOptions.Instructions` rides in every `initialize` and is the one lever that shapes assistant behaviour across a whole conversation.
- **Trip import** (`trip_import_service.go`, specs/import-trip-from-ai-chat): `importTripCore` is the reusable extract→resolve→persist pipeline (handler-free so a future MCP-connector tool can call it). Coordinate tiers: Google Places hit (authoritative) > plausible model coords (kept, flagged approximate) > dropped-with-named-warning; Places **outage/quota is distinguished from ZERO_RESULTS** (`isPlacesZeroResults`) — outage rides one aggregate warning + retryable 503, never per-place blame. Imported trips set `trips.chat_id` (fresh `chat-<token>` lineage) but write **no** `plan_chat_sessions` row — refine-in-chat binds via chat_id and the first refine creates the row. The `import.*` catalog keys are the documented exception to "writeJSONError strings are not localized" (i18n.go header); the Flutter screen shows only 422/429 server messages verbatim. Guards: own IP bucket, per-user `FREE_IMPORTS_PER_DAY` (default 10), trip-cap pre-check before any model/Places spend, `importMaxLocations` cap with a visible warning.
- **Derived-leg identity & per-trip endpoints** (`booking_todo_identity.go`, `plan_trip_origin.go`, migration 00064; specs/trip-endpoint-airports): a derived transport row's identity is NOT its endpoint labels. The two home legs key on a reserved `@home` token whose POSITION carries the direction (`transport:@home>>amsterdam` / `transport:rome>>@home`), with `role`/`origin_label`/`destination_label` as columns — so changing an airport is an in-place title/label update the batch upsert already performs, and the two directions never collide (a trip can leave from ALB and come home into EWR). - **A widget test cannot see a font, so it cannot answer a layout question.** `src/packages/flutter-app/test/` has **no `flutter_test_config.dart` and loads no font assets**, so every widget test lays out in Flutter's built-in test font — a fixed-width stand-in, *wider* than Inter at the same size. Every width, height, line count, wrap point, fold position, ellipsis and overflow in a widget test is therefore a fact about that stand-in, and none of them transfers to the shipped app. This has produced three separate false conclusions in one feature (the travel atlas): a "both header actions share one line" test that pinned a three-line stack the app never renders, a pair of position assertions that only described the test font, and a chip tap at a fixed offset that landed off-screen and made its test pass vacuously. PR #511 exists mostly to undo them. **So: never write, and never restore, an assertion that depends on rendered text size.** What a widget test CAN hold is everything font-independent — which widget is inside which, presence and absence, a state or callback, a color or other resolved property, a constant the code sets outright (`SizedBox(height: kAtlasPlateHeight)`), and a runtime fact the framework itself reports. A claim about the fold, the wrap, or what fits is **verified in the browser at real widths in both languages** and then written down as a comment saying so and saying the assertion is deliberately absent — a test modelling the wrong fold is worse than no test, because it fails on correct code and passes on broken. Two consequences worth knowing: rigid chrome elsewhere on a page can overflow in the test font and not in the app (consume it with `takeException`, and assert it is the ONLY one, so a real second overflow still fails), and a `tap()` positioned by preceding text needs `scrollUntilVisible` — a bare `tap()` on an off-screen widget only WARNS, it does not fail.
